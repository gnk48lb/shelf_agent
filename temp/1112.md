**主要问题**
1. **必修：message 文案泄漏故障。**
   - 例如 install 装少了会返回"补装未达目标数"，螺丝掉在箱外会返回"最后一颗掉在箱外"。
   - 真卡住和前置不满足的文案也不同，agent 能据此区分。
   - ReAct 看到的 JSON 里就有这些字句，demo 时间线上也有。
   - 规格 §3.1 明确说过 install / carry 只返回 status 和耗时，这是实现违规。测试只查了几个英文枚举词，所以没拦住。
   - 规则策略不读 message，所以 sweep 数字不受影响。
2. **README 有一段因果解释是错的。** 它说 rule_noisy 和 rule_oracle 一致，是"每次搬运前都重新验证"。实际搬运前只验证一次，误报会直接放行。
   - 默认噪声下，5000 seed、故障率 0.3：rule_noisy 有 17 次 FALSE_FINISH（0.34%），rule_oracle 为 0。
   - 100 seed 看不出差别，是样本太小。把噪声调高后差距明显。
3. **"换策略不会改变某技能第 n 次调用的故障命运"这个保证不成立。** `randint` 的底层抽取次数随上下文变化。故障率 0.3、前 6 次 install 里约 10.8% 的 seed 会走样。对现有三个策略影响很小，但 README 里写了这条保证。
4. **静默出错的隐患。**
   - 配置里的拼写错误和越界值都会被接受。
   - `--policies rule_noysy` 拼错会正常跑完，但实际用的是 oracle 验证器，却以错误标签入表。
5. **小问题。**
   - `reset(all)` 的"不必要重置"计数口径不对。
   - 转移表 36 个条目里只有 9 个真被用到。
